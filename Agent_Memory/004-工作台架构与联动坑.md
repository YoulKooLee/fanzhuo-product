## 1. 工作台整体架构 [原ID 73515890]

- 工作台根：`C:\Users\游翔\Documents\AI work\Axhub\`（01-项目/02-模板/axhub-manager/06-运行脚本）。

## 2. 53817 make-server active 错位根因与根治补丁 [原ID 30964272]

- 根因：53817 make-server 全局单例。`activeProjectId` 被其他项目 dev stack 启动时的 `setActiveProject`（cli.mjs，无保护）覆盖，导致本项目预览代理 `resolveRuntimeOriginForProxy` 拿不到正确 `runtime.origin` → 503「Make 客户端未启动」→ 预览页缺 bootstrap + `axhub.quickEdit` handler → 握手失败。
- 关键事实：
  - `/prototypes/*` 强制要求 projectId（URL 或 referer），否则 503。
  - `axhub.quickEdit` 握手处理器在 make-server 顶层路由 `/runtime/quick-edit.js`，与 dev-template-bootstrap 无关。
  - `__RUNTIME_ORIGIN__` 不在预览页是预期的。
  - 注册表 `~/.axhub/make/projects.json`，activeProjectId 即当前 active。
- 已实施根治补丁（2026-08-26）：给 cli.mjs 的 `setActiveProject(id)` 加保护——当前 active 项目 runtime 仍在运行、且新目标项目尚未运行时，不抢占 activeProjectId（用 `readServerInfo`+`isLiveMakeClientRuntime` 同步判断）。
  - 原文件备份：`C:\Users\游翔\Documents\AI work\Axhub\03-备份\make-cli.mjs.pre-patch.bak`
  - 重装后一键复打：`C:\Users\游翔\Documents\AI work\Axhub\03-备份\apply-active-guard.mjs`（node 运行）
  - 风险：想把 active 切到一个"尚未运行"的项目会被保护拦住（需该项目 runtime 起来后再切），属可接受取舍。
- 旧记忆「isReusableRuntimeOrigin 严格匹配→端口冲突」因果链在 v0.6.21 不成立（cli.mjs 无该函数），作废。

## 3. 启动开发栈必点两次根因与修复 [原ID 76268127]

- 根因不是 syncMakeActiveProject 失效，而是**状态机没有"启动中"过渡态**：POST `/api/projects/open` 时 spawn PS1（首次 70 秒/后续几十秒），此刻 Vite 还没起来、心跳文件不存在；前端每 5 秒轮询 `GET /api/context/current` 触发 `reconcileWorkspaceCtx`，`isProjectAlive` 返回 false → 立即把项目降级 stopped。等 PS1 完成时项目早被标 stopped，且 Make active 未切 → 浏览器看到「Make 客户端未启动」。第二次点启动时 PS1 检测到 Vite 已就绪秒 done，syncMakeActiveProject 立即生效 → 成功。
- 修复：
  1. 新增 `starting` 状态，`onProjectStarted` 把启动项目设为 starting（而非直接 editing/active）。
  2. `reconcileWorkspaceCtx` 对 starting 不降级（若 Vite 已起则补升级 editing/active）。
  3. PS1 stdout 含 `AXHUB_LAUNCH_STATUS: done` 时调 `markProjectRunning` 把 starting→editing/active + syncMakeActiveProject。
  4. 前端 ctxStatusMap 加 `starting:'启动中'`。

## 4. Make 联动时序：syncMakeActiveProject 必须等依赖就绪 [原ID 52220761 / 79558564]

- 启动开发栈没启动 Make 客户端的根因：server.mjs 的 `/api/projects/open` 在 spawn PS1 之后立即调 `syncMakeActiveProject(relative)`，但 Make 53817 是 PS1 步骤 3 才启动的，HTTP 探测 status=0 失败。
- 修复：在 `child.stdout` 监听里加判断——若输出含 `AXHUB_LAUNCH_STATUS: done`（PS1 8 步全走完、Make 已就绪），再调一次 `syncMakeActiveProject(relative)`。原 spawn 后调用保留作 best-effort。
- activeProjectId 错位（指向 demo-showcase 而非刚启动的项目）→ 浏览器 `http://localhost:53817/?projectId=xxx` 显示「Make 客户端未启动」。
- 手动验证：`PUT http://localhost:53817/api/projects/active {projectId:"xxx"}` 可立即生效。
