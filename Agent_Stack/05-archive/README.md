# 05-archive — 冷回溯归档

> 作用：历史会话、复盘总结、问题排查记录按年月归档。需要时检索（对应文章第二层 Session Archive）。

## 归档结构

```
05-archive/
├── 结项/
│   └── <项目名>-<日期>/     # 项目结项归档（project-memory.md 副本等）
└── 2026/
    ├── 08/
    │   ├── 复盘-xxx.md      # 复盘总结
    │   └── 排查-xxx.md      # 问题排查记录
    └── ...
```

## 归档规则

- **命名**：`类型-主题-日期.md`（如 `复盘-状态机必点两次-20260818.md`）。
- **内容**：日期 / 场景 / 根因 / 处理 / 结论，与 Agent_Memory 的坑记录格式一致。
- **关系**：
  - 归档 = 原始事件的完整记录（冷回溯，按需检索）。
  - Agent_Memory = 提炼后的坑（语义记忆，常驻索引）。
  - 03-rules = 提炼后的规则（热记忆，触发命中）。
  - 一条排查 → 可能同时写归档（完整）+ 提炼进 Agent_Memory + 提炼成 rule。

## 何时检索归档

- 处理任务需要回溯历史决策/旧问题处理过程时。
- 当前规则库命中不到，需要看历史原始记录时。

## 结项归档（2026-08-18 起）

- 项目结束（用户说「结项 / 归档项目」）时执行 `06-reflection/反思协议.md` 第五节。
- 可跨项目复用的方法论 → 提炼到 `03-rules/`（scope: universal/workspace）；项目专属经验 → 移入 `结项/<项目名>-<日期>/`。
- 结项归档后，项目记忆不再影响其他项目。
