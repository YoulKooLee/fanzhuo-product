# 反思协议（Reflection Protocol）— 手动触发

> 对应 C 档「反思检索」（文章 Hindsight 的 reflect 能力）。**默认不自动反思**，只有用户主动要求（说"反思" / "复盘记忆" / "整理记忆"）时才执行。
> 目的：把分散的记忆碎片做「关联 / 去重 / 矛盾检测 / 时序整合」，让记忆从"存起来"升级为"想清楚"。

---

## 一、触发方式

| 触发 | 说明 |
| --- | --- |
| 用户说「反思」 | 触发全量反思 |
| 用户说「复盘记忆」 | 触发全量反思 |
| 用户说「整理记忆 / 优化记忆」 | 触发全量反思 |
| 用户说「这条记忆对不对」 | 触发单条反思 |
| **无上述指令** | **不反思**，只按正常流程记录 |

> 铁律：**默认不反思**。每次踩坑/修复只按「主动写」规则记录原始坑 + 提炼规则，**不自动调反思**，避免额外 LLM 开销和打断。

---

## 二、反思流程（用户要求时执行）

### 步骤1：全量扫描
读取 `Agent_Memory/*.md` 和 `03-rules/*.md` 的所有记忆/规则，收集：
- 每条记忆的 id、category、date、status
- 每条规则的 id、trigger、rule、reason

### 步骤2：三类检测

**① 关联检测**：同一根因的多条记忆 → 归并/交叉引用。
- 例：`001 #1`（launch-log append）与 `001 #2`（缺过渡态）同属"必点两次"，应交叉引用。

**② 去重检测**：内容重复的规则 → 保留一条，其余标注 superseded。
- 例：若 `R-SCRIPT-06` 与 `R-SCRIPT-07` 语义重叠，需明确边界。

**③ 矛盾检测**：相互冲突的规则/记忆 → 标出冲突，说明取舍。
- 例：若某旧规则说"删锁文件"，与新铁律"永不删锁文件"冲突，旧规则标 `invalid + superseded_by=R-SCRIPT-05`。

### 步骤3：时序整合
对同一主题（如"必点两次"）的记忆，按日期排出时间线，补一段「演进结论」：
```
2026-08-12 缺过渡态 → 2026-08-12 Vite+Make双依赖 → 2026-08-13 launch-log append
→ 结论：三坑同源，统一由 R-START-01~05 覆盖
```

### 步骤4：输出反思报告
把反思结果写成一份报告，放在 `05-archive/YYYY/MM/反思-主题-日期.md`，内容含：
- 关联表（哪些记忆相互引用）
- 去重表（哪些规则被合并）
- 矛盾表（哪些规则冲突及取舍）
- 演进结论（主题时间线）

### 步骤5：落地修改
按反思结果更新：
- 冲突/过期规则 → 在 `03-rules/` 改 `status: invalid` + 加 `superseded_by`
- 关联记忆 → 在 `Agent_Memory/` 加交叉引用
- 索引 → 更新 `03-rules/rules.index.json`

> **反思报告写入 archive，不直接删任何记忆**（保留溯源）。

## 三、与"主动写"的关系

| 动作 | 触发 | 内容 |
| --- | --- | --- |
| 主动写（正常流程） | 每次踩坑/修复后 | 记原始坑 + 提炼规则，**不反思** |
| 反思（手动） | 用户明确要求 | 关联/去重/矛盾/时序整合 |

**主动写是增量积累，反思是定期整理**。反思不改变"主动写"的记录方式，只在用户要求时做一次系统性梳理。

---

## 四、默认不反思的原因

1. **节省开销**：每次写入都调 LLM 反思，成本高（文章 C 档/ Hindsight reflect 的代价）。
2. **不打断流程**：踩坑修复时反思会拖慢主任务。
3. **记忆量小**：你的 Axhub 记忆约 14 条，按需整理即可，无需实时反思。

> 结论：**反思是 on-demand 动作**，不是默认行为。需要时喊一声"反思"即可。

## 五、结项归档流程（项目结束，手动触发）

> 触发词：用户说「结项 / 归档项目 / 项目结束」时执行。配套文件：项目根目录 `project-memory.md`（见 02-模板 模板）。

### 步骤1：扫描项目记忆
读取项目根目录 `project-memory.md` 的「项目画像 / 项目经验」，盘点全部项目专属内容。

### 步骤2：提炼（跨项目复用 → 工作台层）
把**可跨项目复用**的方法论提炼为 Agent_Stack 规则：
- 写进 `03-rules/` 对应文件（新规则 id，补 `scope: universal` 或 `workspace`）
- 同步 `03-rules/rules.index.json` + `04-router/router.json`（scope 过滤）
- 必要时升级 `01-skill/`（补 scope）

### 步骤3：归档（项目专属 → 05-archive）
项目专属经验（需求、风格、大屏比例等）移到：
`Agent_Stack/05-archive/结项/<项目名>-<日期>/`（含 `project-memory.md` 副本）。

### 步骤4：清理
- `project-memory.md` 三区填「结项状态」（结项日期 / 提炼的规则 id / 归档位置）。
- 按用户意愿删除已归档/无保留价值的项目内记忆（遵守 R-FILE-02 先备份到 03-备份）。

> 原则：**可复用方法论上升，项目专属经验归档或丢弃**——项目记忆只对项目本身有意义，结项后不留在通用层影响其他项目。
